# InkTrace V2.0“接着写”封版总结

版本：v1.0

日期：2026-07-12

状态：本地封版完成，待 CI 复验

## 一句话说明

“接着写”不是让 AI 接管小说，而是让作者说清下一章想看什么，系统先写一份独立新稿，再由作者决定是否采用、是否继续。

## 这次解决了什么

旧入口更像技术控制台：作者需要理解自动队列、模式、目标参数和系统状态。封版后的入口改成小说作者熟悉的表达：

1. 下一章，你最想看到什么？
2. 选一个方向，或者写一句自己的想法。
3. 写一章给我看。
4. 写完先看稿，再决定是否放进正文、是否继续下一章。

高级章数、篇幅和用量保护仍然存在，但统一收进“更多保护设置”，不打断普通作者的主路径。

## 最终产品决定

- 面向作者的名称固定为“接着写”。
- 内部继续使用 AutoQueue、`auto-queues` 等技术名称，避免重复建模。
- 只有逐章确认一种模式，不再提供连续自动推进。
- 作者意图允许为空，最多 60 字。
- 三项快捷方向只是可编辑预填，不是新的领域状态或接口枚举。
- 每次生成的内容仍是 CandidateDraft，与正式正文隔离。
- “继续写下一章”和“放进正文”是两个独立的真实用户决定。

## 实现范围

### 前端

- 新增三项白话方向与自由输入。
- 新增“不用补充，直接接着写”。
- 明确显示“只会写一份新稿，不会改动你的正文”。
- 隐藏默认态技术词，保留折叠的保护设置。
- 沿用 InkTrace 现有工作台样式与无障碍交互。

### 后端

- 启动请求增加可选 `user_instruction`。
- 后端独立校验 60 字上限。
- 应用服务将最终意图传给既有多章续写会话。
- 未新增数据库字段、领域状态或错误码。
- 通用 Job payload 不保存完整写作意图。

### 文档

- 需求、架构、概要、P2-04、P2-11、P2-12 和开发计划已统一方案 A 口径。
- 旧验收清单中的 continuous 模式结论已删除。
- README、当前状态、作者说明和最终验收报告已更新。

## 不包含什么

本次没有实现以下能力：

- 自动把新稿放进正式正文；
- 自动替作者接受或拒绝候选稿；
- 无人值守连续生成多章；
- 绕过冲突、记忆或人工审核门；
- P3 多人协作、云同步或发布管理。
