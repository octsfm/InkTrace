## 一、文档定位与设计目标

### 1.1 本文档管什么

| 覆盖 | 不覆盖 |
|---|---|
| UI 入口位置（按钮、Tab、路由） | 后端领域模型 |
| 组件容器类型（Panel / Drawer / Modal / Popover / Toolbar） | API 请求/响应结构细节 |
| 交互状态（loading / empty / failed / stale / warning 等） | 数据库表结构 |
| 用户确认规范（哪些需确认、哪些不需要） | Store 内部实现 |
| Feature Flag 显示规则 | Service 层逻辑 |
| 用户可见中文文案 | — |

### 1.2 设计原则

1. **增量不推翻**：基于现有 V1.1 Workbench / WritingStudio / RightWorkspacePanel / PureTextEditor 继续设计，不重做。
2. **优先复用**：优先使用现有组件、布局、颜色、按钮样式、提示样式。
3. **操作短路径**：常用功能 1~2 步完成，危险操作才需二次确认。
4. **中文优先**：用户可见文案尽量使用中文白话，不夹杂英文（代码名、接口名、状态枚举除外）。
5. **写作优先**：AI 功能是"写作助手"，不是"后台管理系统"。界面应是明亮、简洁的写作工具风格。
6. **确认不滥**：常用动作不过度确认；危险动作才弹二次确认。
7. **AI 不自动写正文**：所有 AI 产出必须经用户确认后才进入正式数据或编辑器草稿。

### 1.3 核心约束

- 不破坏 PureTextEditor 核心编辑能力。
- 不破坏 V1.1 Local-First 草稿保存链路。
- CandidateDraft、AISuggestion、SelectionRewrite、OutlineAssist、Opening 等都必须经过用户确认。
- 成本看板、分析看板不触发 LLM 调用。
- P2 UI 通过 Feature Flag 分期启用。
- P1 组件优先通过 props / slots / composable / Store 扩展。

### 2.2 右侧面板 Tab 控制策略（冻结）

#### 核心规则

1. **P2 不改变 V1.1 既有 Tab 的优先级和位置**。V1.1 已有的人物、设定、时间线、伏笔等 Tab 保持不变。
2. P2 新增的 AI 功能入口**统一收敛到"AI 助手"聚合 Tab**，不分散插入主 Tab 列表。
3. 若 V1.1 已有 Tab 数量达到上限，P2 功能默认进入"AI 助手"内部子视图或"更多"菜单，**不强行挤占主 Tab 位**。

#### 推荐布局

| Tab 类型 | 内容 | 说明 |
|---|---|---|
| **V1.1 固定 Tab** | 候选稿、人物、设定、时间线、伏笔等 | 不受 P2 影响，保持原有位置 |
| **AI 助手（P2 新增聚合 Tab）** | 接着写、大纲辅助、开篇助手 | 内部子 Tab 或下拉切换。Feature Flag 控制整个聚合 Tab 的可见性 |
| **"更多"菜单** | 低频或溢出功能 | 若"AI 助手"中所有子功能对应的 Feature Flag 均为 false，则"AI 助手"Tab 本身也隐藏 |
| **独立页面** | 成本看板、分析看板 | 不在右侧面板中 |

#### 显示条件

- Feature Flag=false 的功能在 AI 助手内部不可见。
- 若 AI 助手内部所有子功能的 Flag 均为 false，整个"AI 助手"Tab 隐藏。
- 小屏幕下（宽度 < 1200px），AI 助手退化为工具栏下拉菜单入口。

## 三、P2-S1 UI 集成

### 3.1 多章续写（MultiChapter）

**入口**：顶部工具栏"多章续写"按钮（图标 + 文字，Feature Flag 控制）。

**容器**：`MultiChapterPanel` — 从右侧滑入的 Drawer（宽 420px），不遮挡编辑区主体。

**布局**（运行中）：
```
┌─ 多章续写 ───────────────────────── [✕] ─┐
│                                            │
│  进度：■■■■■□□□□□  5 / 10 章             │
│  字数：25,000 / 50,000                      │
│                                            │
│  ┌ 章节状态 ──────────────────────────┐   │
│  │ ✅ 第1章  3,200字  已生成           │   │
│  │ ✅ 第2章  2,800字  已生成           │   │
│  │ 🔄 第3章  生成中…                  │   │
│  │ ⏳ 第4章  等待中                   │   │
│  └────────────────────────────────────┘   │
│                                            │
│  当前章节需要你确认：                        │
│  [查看候选稿]  [确认并继续]  [停止续写]      │
└────────────────────────────────────────────┘
```

**状态与文案**：

| 内部状态 | 用户看到 | 可用操作 |
|---|---|---|
| `generating` | "正在生成第 N 章" | 停止 |
| `waiting_review` | "第 N 章已生成，需要你确认" | 查看候选稿、确认并继续 |
| `blocked` | "当前结果需要你处理" | 查看详情、跳过、停止 |
| `completed` | "全部章节已生成" | 查看所有候选稿 |
| `failed` | "第 N 章生成失败" | 重试、跳过、停止 |

**约束**：
- 不自动应用候选稿到正文。用户必须手动进入候选稿区 apply。
- 停止后已生成的候选稿全部保留。
- "[查看候选稿]"点击后：切换到右侧面板"候选稿"Tab，自动滚动到当前章节对应的候选稿。不弹出新窗口。

### 3.2 CitationLink（引用校验）

**入口**：候选稿正文中带下划线的引用标记。无独立入口按钮。

**容器**：`CitationPopover` — 点击引用标记时弹出小气泡（宽 320px）。

**状态与文案**：

| 内部状态 | 用户看到 | 视觉效果 |
|---|---|---|
| `verified` | "已找到来源" | 绿色小勾 + 灰色下划线 |
| `low_confidence` | "可信度较低，请简单看一下" | 黄色小感叹号 + 虚线下划线 |
| `source_missing` | "暂时找不到来源" | 灰色小问号 + 虚线下划线 |
| `unverified` | "尚未检查" | 无特殊标记 |

**约束**：
- 低置信**不阻断**候选稿展示，仅做温和提示。
- 不弹出 Modal 打断阅读。

### 3.3 StyleDNA（风格画像）

**入口**：设置页中的"风格画像"入口，具体路由以现有设置路由体系为准（建议 `/works/:workId/style` 或 `/settings/ai/style-dna`，以 P2-11 路由注册确认为准）。非 WritingStudio 内嵌面板。

**容器**：`StyleDNAConfigPanel` — 独立页面内的卡片式布局。

**流程**：导入样本 → 分析中 → 查看结果 → 确认启用（3 步）。

**状态与文案**：

| 内部状态 | 用户看到 | 可用操作 |
|---|---|---|
| `none` | "尚未配置风格画像" | 导入样本 |
| `extracting` | "正在分析你的风格样本…" | 取消 |
| `pending_confirm` | "分析完成，请确认是否启用" | 确认启用、放弃 |
| `active` | "已启用为当前作品风格参考" | 禁用、重新提取 |
| `disabled` | "已停用，不再参与生成" | 重新启用 |

**约束**：
- 未确认的风格画像**不能**注入 ContextPack。
- 低置信度（<500 字）时展示明确提示，但不阻止用户确认启用。
- 同一作品同时只有一个 ACTIVE 风格画像。

### 3.4 接着写（内部 AutoQueue）

**入口**：右侧面板“AI 助手”聚合 Tab → “接着写”子视图（Feature Flag 控制）。

**容器**：`AutoQueuePanel` — 右侧面板内的卡片式布局。

**布局**（未启动时）：
```
┌─ 接着写 ─────────────────────────────────┐
│  说想法 → 写一章 → 你来看 → 再决定        │
│                                           │
│  下一章，你最想看到什么？                  │
│  [让冲突更紧张]                            │
│  [让人物关系推进]                          │
│  [把刚才的伏笔接下去]                      │
│                                           │
│  [或者写一句你自己的想法……]        0/60  │
│                                           │
│  只会写一份新稿，不会改动你的正文。        │
│  写完先给你看。                            │
│  [写一章给我看]                            │
│  [不用补充，直接接着写]                    │
│  ▸ 更多保护设置                            │
└──────────────────────────────────────────┘
```

**输入规则**：三项快捷选择只负责把白话建议填入同一个可编辑输入框；作者继续修改后，以输入框最终内容为准。最多 60 字，实时显示计数；允许不选、不填并直接接着写。主按钮不要求作者先理解“配置”或另点保存，已有目标篇幅、章数和用量保护收进“更多保护设置”。默认态不得出现队列、Token、Prompt、Session 等技术词。

**生成后**：候选区显示“新写的一章 · 还没有放进正文”，提供既有查看、放进正文、放弃操作。放进正文必须单独通过 HumanReviewGate；继续下一章只通过逐章确认门，二者互不代替。

**停止通知示例**：
```
达到用量上限：🛑 这次续写已到你设置的上限 · 已用约 52 万 / 上限 50 万 AI 用量
             当前章节完成后已停下，4 章候选稿都还在。
             [调整预算]  [继续保持停止]

连续发现问题：🛑 这次续写已停下 · 连续 2 章发现需要你处理的问题
               已生成 5 章候选稿，全部保留在候选稿区。
               [看看是什么问题]  [处理后继续]  [结束这次续写]

手动停止：🛑 你已停下这次续写 · 已生成 3 章候选稿
          [继续]  [结束这次续写]
```

**约束**：
- 逐章确认是唯一模式；每章候选稿就绪后，内部状态固定为 `WAITING_USER_DECISION`，界面显示“等待你确认”。
- 只有作者点击“继续写下一章”后才发送 `confirm-continue`；不得提供连续推进开关或自动触发该请求。
- `confirm-continue` 与 CandidateDraft apply 是两个独立操作，继续下一章不代表采用当前候选稿。
- 停止后不删除已生成的候选稿。
- blocking 后必须停止或暂停，不得推进下一章。

## 四、P2-S2 UI 集成

### 4.1 @Mention（实体引用）

**入口**：编辑器内输入 `@` 触发。无独立 UI 入口。

**容器**：
- `MentionPopup` — 输入 `@` 后在光标附近弹出建议列表（宽 280px）。
- `MentionHighlight` — 已插入的 Mention 在正文中以浅蓝底色 + 虚线下划线高亮。
- `MentionTooltip` — Hover 已插入 Mention 时弹出信息浮层。

**空状态**：
```
┌─ 没有找到相关角色或设定 ──────────────────┐
│  试试其他关键词，或 [新建角色]               │
└──────────────────────────────────────────┘
```

**约束**：
- 不直接触发 LLM 调用。
- "[新建角色]"点击后：若 V1.1 已有角色创建入口（如右侧人物面板的"添加角色"），则跳转到该入口（不重复造轮子）；若不存在，弹出轻量侧边小表单（非 MentionPopup 内嵌），创建完成后自动回到编辑器，新建角色出现在下次 @ 建议列表中。不在 MentionPopup 内承载复杂表单。
- 弹窗按 Esc 可关闭，不打断用户正常输入。

### 4.2 开篇助手（Opening Agent）

**入口**：顶部工具栏"开篇助手"按钮，或右侧面板"AI 助手"→"开篇助手"。

**产品内名称**：只显示“开篇助手”，不显示 Opening Agent。

**容器**：`OpeningAgentWizard` — 宽 720px 的分步 Modal。弹窗承载短向导，不承载后台日志或长期运行详情；退出后可从已保存业务状态继续。

**默认四步流程**：

1. **说说你的故事**：默认带入题材、简介、大纲和人物信息，只追问“什么故事、主角想要什么、第三章后希望读者期待什么”。
2. **选择开篇方向**：展示三个白话方向，每个只含名称、百字说明、前三章一句话安排、优点和风险。
3. **生成前三章候选稿**：按章生成，可停止；已完成章节保留。
4. **逐章阅读与决定**：进入现有候选稿区，逐章应用、修改、重写、丢弃或稍后处理。

**灵感参考是可选项**：第一步底部折叠显示“添加灵感参考（可跳过）”。无参考作品是完整可用的默认路径。添加时最多 3 部、每部最多前 3 章且不超过 30,000 汉字；超限要求用户裁剪，不静默截断。

**版权交互**：只有用户主动添加参考文本时显示一次版权确认。前端未勾选时不能提交，后端仍必须验证确认字段；生成前不重复要求第二次版权勾选。

**风险交互**：

- 生成前策略相似风险 high：不允许生成，提示“这个方向和参考作品的关键安排太接近，请先换一种开场方式”。
- 生成后稿件原创性 high：候选稿仍可查看，但“应用到章节草稿”不可用，提供“按建议重写”。
- 风险门控必须由后端执行，前端 disabled 不是安全边界。

**作者可见进度**：只显示“正在准备第 N 章”和本章目标，不显示 Agent、Job、Session、Prompt、Token、模型名或内部步骤。

**候选稿边界**：每章独立 CandidateDraft，逐章走 HumanReviewGate；不创建正式章节，不覆盖已有章节，不提供“一键全部应用”。

### 4.3 大纲辅助（Outline Assist）

**入口**：右侧面板"AI 助手"聚合 Tab → "大纲辅助"子视图（Feature Flag 控制）。

**容器**：`OutlineAssistPanel` + 内嵌 `SuggestionCard` 列表。

**第一步只问作者“要整理哪里？”**：

- [整本故事大纲]
- [某一章] → 选择“第 N 章”
- [一段临时文字] → 只能生成建议和复制，不能直接放进正式大纲

“生成本章细纲”必须先选定章节。未选章节时按钮不可用，并提示“先选一章，我才能把细纲放对位置”。

**四个白话动作**：

| 按钮 | 辅助说明 |
|---|---|
| **把这段写顺** | 不改故事意思，只整理表达和顺序 |
| **把这段补完整** | 补足动机、转折、线索或场景安排 |
| **生成本章细纲** | 拆出本章目标、场景、冲突和结尾钩子 |
| **整理本章写作要点** | 做一张本章写作计划，不生成正文 |

生成中只显示“正在整理，请稍等”，不显示 Agent、Job、Session、Prompt、Token、模型名或内部状态。

**大纲建议流程（accept ≠ apply）**：

1. SuggestionCard 展示“当前内容 / 建议内容”的前后对比和 1～3 条变化摘要。
2. 操作按钮为 [先留着] [不要这条]；“先留着”只调用 accept，不修改任何大纲。
3. 已留存的建议出现 [放进大纲]。点击后弹出 Popconfirm：
   - 作品大纲：“确定把这条建议放进整本故事大纲吗？大纲内容会被修改。”
   - 章节大纲：“确定把这条建议放进第 N 章细纲吗？该章细纲会被修改。”
4. 只有作者确认后才发送 `confirm_apply=true`；同时发送统一字段 `target_revision`（当前目标版本）、`caller_type=user_action`、`user_action=true` 和非空 `idempotency_key`。
5. 成功后 toast：“已放进整本故事大纲”或“已放进第 N 章细纲”，2 秒自动消失。

**写作要点流程（无需先 accept）**：

1. 建议卡生成后直接显示 [设为本章写作计划] [不要这条]。
2. 点击“设为本章写作计划”调用 convert，创建尚不能被续写使用的待确认任务。
3. 展示写作目标、必须写到、不要写到、建议字数等白话字段，再显示 [确认使用]。
4. 点击“确认使用”后任务才可供后续续写使用。界面不得出现 WritingTask、pending、ready 等内部词。

**冲突与失败文案**：

- 大纲版本已变化：提示“这份大纲刚刚有改动，请刷新后重新生成建议”，只提供 [刷新大纲] [重新生成]，不提供强制覆盖。
- 其他真实冲突：显示简短原因和 [查看怎么处理]；处理完成后刷新目标并重新生成，不继续使用旧建议。
- 生成失败：保留目标和用户输入，提供 [再试一次]。
- 前端 disabled 不是安全边界，正式门控必须由后端执行。

### 4.4 选区改写（Selection Rewrite）

**入口**：用户在编辑器中选中文本后，浮动工具栏自动出现。

**容器**：
- `SelectionRewriteToolbar` — 选中文末浮动（宽 320px）：[扩写] [重写] [缩写] [润色] [对白优化] [降低 AI 味]
- `SelectionRewriteDiffModal` — 查看 Diff 结果的全屏 Modal（宽 800px）。

**约束**：
- 应用只写入 Workbench Store（编辑器草稿），不直接写后端正式正文。
- 后续保存走 V1.1 Local-First 链路。
- 原文被修改后必须检测冲突（`source_hash` 不匹配 → `conflicted`）。
- 冲突时**不替换**草稿，显示"原文已变化，请重新选择"。
- 撤销在 **Store 层做内存回滚**（恢复应用前的草稿快照），不调用后端 API。5 秒内若触发 V1.1 自动保存，自动保存的是改写后草稿；撤销回滚到应用前快照，与 V1.1 已有 undo 逻辑一致。

## 五、P2-S3 独立看板页面

### 5.1 AI 用量与预算（CostDashboard）

**路由**：`/works/:workId/cost`。历史查询不要求 Provider 或 API Key 当前可用；页面内预算保护是受控用户写，不得把整个页面误称为纯只读。

**页面目标**：普通小说作者无需理解 Token、Provider 或模型计价，就能先看懂“所选月份大约花了多少、当前月度费用预算还剩多少、预算目前处于什么状态”。页面 GET 不含下一次调用投影，不能承诺“可以开始”；真正开始 AI 操作时由服务端再检查。

**视觉基线**：严格复用 `InkTrace-DESIGN.md` 的 CSS 变量和 Card/Button/StatusBadge/Modal/Toast 规范；禁止硬编码颜色、字号、间距、圆角和阴影。页面保持白底、轻边框、大留白与低干扰，不做后台管理表格风、日志终端风或复杂动效；错误只显示 safe_message。

**信息顺序**：

1. 标题“AI 用量与预算”、作品名、更新时间、刷新。
2. 月份切换。
3. 当前月显示：“本月预计费用”“本月费用预算还剩”“本月预算状态”。
4. 历史月份改为：“{YYYY 年 M 月}预计费用”“AI 用量”“使用次数”，不展示不存在的历史剩余预算。
5. “预算保护”。
6. “用量趋势”。
7. 默认折叠的“费用花在哪里”（模型分工/模型名称/模型服务）。
8. 默认折叠的“查看使用明细”。

**固定说明**：

> 根据每次使用时保存的价格估算，可能与 AI 服务商的最终账单略有不同。

**当前月三个首要答案的取值**：

| 卡片 | 有可靠数据 | 无预算/无法核算 |
|---|---|---|
| 本月预计费用 | 按币种分别显示已知金额 | unknown 显示“有些费用算不出来”，不显示 0 元 |
| 本月费用预算还剩 | 只计算 monthly 同币种 `上限 - 已知已用`，最低显示 0 | 未设置显示“还没设置”；无法判断时显示“暂时算不出” |
| 本月预算状态 | “目前未到上限”或“接近上限” | 未设置/关闭显示“没有预算保护”；确定超限显示“新的 AI 操作先停一下”；无法判断显示“费用没算清，先停一下” |

initialization/auto_queue 的单位和适用时机不同，只在“预算保护”区分别展示，不得与 monthly 合成一个“预算还剩”。预算保护区始终标注“当前设置，只影响现在和之后”，历史月份也不例外。

**费用完整度**：

| API 状态 | 页面表达 |
|---|---|
| `complete` | 显示分币种预计费用 |
| `partial` | “已知预计费用 {amounts}，另有 {N} 次费用无法计算” |
| `unknown` | “费用无法计算。这些使用没有保留当时价格，系统不会用现在的价格倒推。” |
| `empty` | 当前月：“这个月还没有使用过 AI 功能”；历史月：“{YYYY 年 M 月}没有 AI 使用记录” |

不同币种分别显示，例如“¥2.35 + US$0.18”，不得合成一个金额。unknown 不得显示 `¥0.00` 或“免费”。

AI 用量另有独立完整度：只有已知记录才计入数值，并同时显示“另有 N 次用量记录不完整”；不得把未知调用加成 0。所选月份/时间范围跨过保留水位时，在筛选区下方显示“这里只保留从 {date} 开始的记录”，不把受限范围冒充完整。

**预算名称**：

| 内部类型 | 作者看到的名称 |
|---|---|
| `initialization` | 整理整本作品 |
| `auto_queue` | 一次“接着写” |
| `monthly` | 每月预计费用 |

“每月预计费用”是默认主设置；“整理整本作品”“一次接着写”收进 [更多保护]。每次只填写一个上限，不同时暴露费用/Token 两套字段；提醒选项使用“提前一些（70%）/一般（80%）/快到上限时（90%）”。费用/趋势为空不隐藏预算区，仍显示 [设置预算]，允许作者在第一次使用 AI 前先设保护。

AI 用量上限以“万 AI 用量”输入，旁注“包括 AI 阅读和生成的内容，不等于小说字数”。有历史时显示“参考：最近通常约 X 万，建议上限 Y 万”；没有历史时不自动填一个看似精确的数字，提示先使用一次或先只设每月金额。

当前预算来源必须可见：作品级显示“这本作品的设置”，提供 [改回默认设置]；继承全局时显示“默认设置”，提供 [为这本作品单独设置]。两者都用 PUT 保存继承状态，不物理删除。预算并发冲突时刷新服务端最新值、保留用户草稿并聚焦提示：“预算刚刚在别处改过，已刷新最新设置。请看一眼后再保存。”

**预算状态展示**：

| 用量区间/判定 | UI 表现 | 冻结文案 |
|---|---|---|
| 月度低于提醒阈值 | 正常图标 + 文字 + 具体用量 | “目前还没有到你设置的费用上限。真正开始下一次 AI 操作时，系统会再检查。” |
| 未设置预算 | 中性图标 + 说明 | “目前没有设置预算保护。你仍可使用 AI，但系统不会在费用接近上限时替你停下。” + [设置预算] |
| 预算保护已关闭 | 灰色图标 + 说明 | “这项预算保护已关闭。AI 使用不会受这个上限限制。” + [重新开启] |
| 月度达到提醒阈值 | 提醒图标 + 黄色辅助色 + 百分比 | “这个月已经用了 {percent}%，快到你设置的费用上限了。” |
| 月度刚好到上限 | 停止图标 + 文字 + 100% | “这个月刚好用到你设置的费用上限。还没有超出，但新的 AI 操作需要先调整预算。” |
| “接着写”达到提醒阈值 | 提醒图标 + 黄色辅助色 + 百分比 | “这次续写已经用了 {percent}%，快到你设置的上限了。” |
| 整理作品达到提醒阈值 | 提醒图标 + 黄色辅助色 + 百分比 | “这次整理作品已经用了 {percent}%，快到你设置的上限了。” |
| 月度确定超限 | 停止图标 + 红色辅助色 + 具体用量 | “这个月已经到你设置的费用上限。新的 AI 操作先停一下；已经开始的这次 AI 操作会先完成，之后不再继续。” |
| 本次确定超限 | 停止图标 + 红色辅助色 | “这次续写已在当前章节完成后停下，已经生成的候选稿都还在。” |
| 整理作品确定超限 | 停止图标 + 红色辅助色 | “整理作品已停下，已经完成的结果会保留。” |
| 当前月费用记录不完整 | 警示图标 + 中性警示色 | “这个月有些使用没有留下完整费用。为了避免继续增加费用，新的 AI 操作先停一下；你的写作内容不受影响。” |
| 当前模型缺少价格 | 警示图标 + 中性警示色 | “这个 AI 模型还没有可用的费用信息，所以暂时不能判断金额预算。” + [完善费用信息] |

| 预算查询失败 | 警示图标 + 中性警示色 | “预算状态暂时没有加载出来。新的 AI 操作先停一下，请稍后重新检查。” |

**空态与刷新**：加载失败显示“AI 用量暂时没有加载出来，你的写作内容不受影响”及 [重新加载]；这是成本页对通用 failed 文案的明确覆盖，不得显示“生成失败”。刷新期间保留旧数据并显示“正在更新用量”，不得整页闪空。趋势图始终跟随所选月份，UI 显式传该月首日/末日；接口“最近 30 天”默认仅供无范围的独立调用。

**无障碍与窄屏**：页面使用明确 h1/h2；月份按钮提供“上一个月/下一个月”可读名称；预算进度条使用 `role=progressbar`、min=0/max=100、now=min(实际百分比,100)，`aria-valuetext` 读真实超额（如“已用 120%，超过 20%”）；ratio=null 时不渲染 progressbar、不播报 0%，改用 status/alert 文字；趋势图同时提供文字摘要或可访问数据表；Modal 圈定焦点、支持 Esc、关闭后焦点回原按钮，有未保存输入时 Esc/关闭/遮罩先确认是否丢弃；字段错误用 `aria-describedby` 关联，校验失败聚焦首个无效字段，保存失败聚焦 alert；加载/成功 polite，阻断/超限/失败 assertive；Toast 不是唯一反馈；窄屏卡片纵排、操作目标不小于约 44px。

### 5.2 费用估算设置

**入口**：复用 SettingsCenter `/settings?section=ai-cost`（作品上下文追加 `work_id`），section 名称“AI 费用与预算”。带 work_id 时顶部固定显示“正在设置：{作品名}”；不带 work_id 才是“所有作品的默认设置”，常驻提示“会影响所有仍在使用默认设置的作品”，按钮叫“保存默认设置”。它始终保留预算保护，并把费用估算放在更多设置；两者都不随 `enable_cost_dashboard` 隐藏。

**小白流程**：

1. 官方已有精确价格时只显示“系统已找到这个模型的费用信息”，不让作者重复填写。
2. 官方价格缺失时，从现有模型配置选择“模型服务/模型名称”，优先提供 allowlist HTTPS [查看官方价格说明]。没有可信链接时明确“不要猜价格，可先不用月度金额保护”。
3. 按官方页面填币种、“每 100 万 AI 输入用量”“每 100 万 AI 输出用量”；解释输入是 AI 阅读、输出是 AI 生成，不是小说字数，并用最近一次完整用量显示只读费用预览，帮助检查单位。
4. 固定提示：“新价格只用于之后的使用，过去缺失的费用不会倒算；填错会让预计费用和金额预算不准确。”保存前勾选“我已按官方价格说明核对”。
5. 保存不额外弹窗；停用不物理删除。若会让正在启用的月度保护无法判断，则不保存并解释如何先处理预算。找不到可靠价格时主按钮为 [暂不手填]。

价格并发冲突时刷新最新值、保留草稿并聚焦提示：“费用信息刚刚在别处改过，已刷新最新设置。请核对后再保存。”用户重新确认后才可保存，不能自动覆盖。

页面不显示 Provider SDK、per-token 算式、price_snapshot、API Key 或原始技术错误。历史缺价只说明无法倒算；只有当前/未来模型缺价才提供 [完善费用信息]，预算查询失败则只提供 [重新检查]。

## 六、统一交互状态规范

所有 P2 组件的交互状态使用统一的中文文案和 UI 表现：

| 内部状态 | 用户看到的中文 | UI 表现 | 可用按钮 | 允许重试 | 阻断流程 |
|---|---|---|---|---|---|
| `loading` | 正在加载… | 骨架屏 / 浅色 spinner | — | — | 否 |
| `polling` | 正在生成，请稍等 | 进度条 + 当前步骤文案 | 取消（如支持） | — | 否 |
| `empty` | 暂无数据 | 空状态插图 + 引导文案 | 引导操作按钮 | — | 否 |
| `failed` | 操作没有完成 | 红色提示条 + 当前组件 safe_message | 重试、取消 | ✅ 是 | 否 |
| `warning` | 提示信息 | 温和黄色提示条 | 查看详情、忽略 | — | 否 |
| `stale` | 数据可能已过期 | 黄色提示条 + 刷新按钮 | 刷新 | — | 否 |
| `conflicted` | 原文已变化，请重新选择 | 橙色提示条 | 重新选择、取消 | — | 是 |
| `feature_disabled` | 这个功能暂未开启 | 空状态页面 | 返回 | — | 是 |
| `budget_exceeded` | 已到你设置的上限 | 停止图标 + 红色辅助色 + 用量详情 | 提高预算、关闭预算保护 | — | 是 |

| `budget_price_unknown` | 费用信息还没设置好 | 警示提示条 + “过去费用不会倒算” | 完善费用信息、继续保持暂停 | — | 是 |
| `budget_currency_mismatch` | 费用单位对不上 | 警示提示条 + 当前预算/AI 费用的中文单位 | 调整月度预算/AI 设置、继续保持暂停 | — | 是 |

| `waiting_user_action` | 等待你确认 | 蓝色提示条 + 高亮确认按钮 | 确认、拒绝、修改 | — | 是 |

| `applied` | 已应用 | 绿色 toast（2s 自动消失） | 撤销（如支持） | — | 否 |
| `rejected` | 已拒绝 | 灰色 toast（2s 自动消失） | — | — | 否 |
| `disabled` | 已停用 | 灰色标签 | 重新启用 | — | 否 |

**通用规则**：
- `failed` 状态**必须**提供重试入口。
- `failed` 的具体文案按动作覆盖：生成类可写“生成失败”，查询类写“暂时没有加载出来”，保存类写“没有保存成功”；禁止所有组件统一显示“生成失败”。

- “重新检查并尝试修复”若仍 unresolved，展开适用出口：月度可等到下月或二次确认关闭保护；整理作品可结束本次并重新开始；“接着写”可结束本次并重新开始；同时存在月度 unknown 时继续说明单次重开不能消除本月缺口。可导出不含正文/Prompt/Key 的安全诊断信息。

## 七、用户确认与防误触规范

### 7.1 必须用户确认的动作

| 动作 | 确认级别 | 确认方式 | 说明 |
|---|---|---|---|
| apply candidate draft | 沿用 P1 既有流程 | P2 不新增确认。若 P0/P1 HumanReviewGate 已有确认，则沿用；若候选稿会覆盖已有正文，显示差异预览 | 不破坏已有链路 |
| 放进大纲（apply outline suggestion） | 轻量确认 | 先展示前后对比，再按目标弹 Popconfirm：“确定把这条建议放进整本故事大纲/第 N 章细纲吗？” | “先留着”不确认；确认后请求必须带 `confirm_apply=true` |
| apply selection rewrite | 普通确认 | 点击即执行（用户已在 Diff 弹窗中看到变化） | — |
| confirm style profile | 普通确认 | 点击即执行（用户已查看分析结果） | — |
| confirm opening strategy | 普通确认 | 点击即执行 | — |
| auto queue confirm continue | 普通确认 | 点击“继续写下一章”后执行（唯一逐章模式核心操作） | 每章 1 次点击；与 CandidateDraft apply 独立 |
| reject candidate / reject strategy | 普通确认 | 点击即执行 | 拒绝不危险 |
| **stop auto queue** | **二次确认** | 弹窗：“确定要停下这次续写吗？已经写好的新稿会保留。” | 中断长任务 |
| 保存/调整预算 | 普通确认 | 用户在表单点击“保存预算”；请求带 `confirm_budget_change=true` | 不额外弹二次确认 |
| 保存/调整费用估算 | 普通确认 | 用户点击“保存费用信息”；请求带 `confirm_price_change=true` | 只影响之后的新调用，不额外弹二次确认 |
| **关闭预算保护** | **二次确认** | 弹窗："关闭预算保护后，AI 功能将不再受这个上限限制，可能产生更多费用。确定要关闭吗？"；请求额外带 `confirm_disable=true` | 可能产生费用 |

### 7.2 防误触规则

1. **loading 态禁用重复点击**：所有提交类按钮在 loading 状态时 `disabled + spinner`。
2. **二次确认弹窗**：标题清晰说明后果，取消按钮在左、确认按钮在右。
3. **toast 提示**：操作后反馈（绿色成功 / 红色失败），2 秒自动消失。**Toast 不做确认用**（确认必须用 Modal 或 Popconfirm）。
4. **撤销入口**：SelectionRewrite 应用后提供"撤销" toast 按钮（5 秒内可撤销）。撤销在 Store 层做内存回滚，不调用后端 API。5 秒内若触发自动保存，自动保存的是改写后草稿；撤销回滚到应用前快照，与 V1.1 已有 undo 逻辑一致。
5. **危险按钮**：停下这次续写、关闭预算、删除风格画像等不可逆操作用红色按钮。
6. **预算写不做乐观覆盖**：提交期间保留原设置并禁用重复提交，服务端成功后才更新；失败提示“预算没有保存成功，原来的设置还在”并提供“再试一次”。
7. **预算调整不自动继续任务**：成功后提示“预算已更新。请回到刚才的 AI 功能，确认后继续”。
8. **本次续写恢复使用新预算**：用户回到“接着写”并明确点“继续”后，系统先用最新预算重新检查；通过才显示“已按新的预算继续”，仍不够则保持停止并说明原因。

## 十、与 V1.1 Local-First 的兼容边界

### 10.1 数据写入路径

```
用户操作 → UI 组件 → Store → API（user_action）→ Service → Database
                                    ↑
                       所有正式写入必经 Presentation API
                                    ↑
                   caller_type = user_action 校验
```

### 10.2 各模块接入规则

| 模块 | 写入路径 | 兼容说明 |
|---|---|---|
| SelectionRewrite | Workbench Store（编辑器草稿）→ Local-First 保存 | 只改草稿，不改正式正文 |
| CandidateDraft apply | HumanReviewGate → V1.1 保存链路 | 走标准路径 |
| OutlineAssist apply | OutlineApplicationService → WritingAssetService | 复用 WorkOutline/ChapterOutline 与 expected_version 保存链路 |
| Opening apply | CandidateDraft + HumanReviewGate | 走标准候选稿链路 |
| StyleDNA | 独立表（`style_profiles`） | 不接触正文 |
| CostDashboard 查询 | 只读 `llm_call_logs` | 不写任何成本事实 |
| CostBudget 预算保护 | user_action → CostBudgetService → cost_budgets/既有 AutoQueueConfig | 不写正文、候选稿或成本事实；必须幂等审计 |
| AnalysisDashboard | 只读 chapters + `analysis_metrics` 缓存 | 缓存写入不接触正文 |

### 10.3 不破坏的 V1.1 行为

- 离开保护（未保存提示）。
- 脏状态标记。
- 自动保存。
- 版本冲突弹窗（VersionConflictModal）。
- Workbench Store 是编辑器草稿状态的唯一入口。
